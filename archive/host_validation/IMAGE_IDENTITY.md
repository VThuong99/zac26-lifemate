# Image identity correction

Docker image-store IDs and image configuration digests are separate values. The failed host smoke's saved `image-inspect.json` reports a Docker schema-2 target descriptor, not the release's configuration digest. The corrected validator derives that descriptor from the sealed archive and checks its digest, media type, size and runtime configuration.

The production CLI has no alternative trust-anchor option. A modified release manifest cannot silently authorize different archives or images.

Verification performs one streaming read of the original archive, computing its compressed SHA-256/MD5 and size while checking gzip integrity. It reads only the small outer metadata and hashes the raw layer stream without extracting or parsing the inner filesystem. The config must hash to the release config ID; its OS, architecture and rootfs must agree with release metadata. The archive manifest must identify exactly that config, layer and tag. Layer bytes must hash to the release DiffID.

The verifier then derives the Docker schema-2 manifest using the verified config digest/size and verified uncompressed layer digest/size. The field ordering and media types match the [containerd Docker-save importer](https://github.com/containerd/containerd/blob/v2.2.0/core/images/archive/importer.go). Hashing those generated bytes reproduces the host's saved target digest. This is a cryptographic derivation, not acceptance based on an observed ID or matching filesystem alone.

Supported identities are the exact config digest for a legacy store, the derived Docker-save target manifest, the authenticated release OCI manifest, and the derived release single-platform OCI index. Containerd identities require an inspected descriptor with matching digest, size and media type. Arbitrary indexes, extra platforms, rewritten manifest encodings or recompressed representations are rejected unless their provenance can be verified by a future explicit implementation. RepoTags/RepoDigests alone do not authenticate an image.

Loaded-image checks cover OS, architecture/variant, RootFS type and ordered DiffIDs, entrypoint, command, environment, working directory, user, labels, volumes, exposed ports, healthcheck, shell, OnBuild hooks, stop behavior, networking and terminal/input defaults. API-elided null/empty defaults are normalized. Environment order is irrelevant, but duplicate names are rejected. Unknown configuration keys fail closed. Descriptor annotations and store timestamps are transport metadata rather than runtime identity.

The runner records and executes the verified immutable store reference, rather than the mutable tag or an assumed config ID. Before inference, `container-image-check` verifies the created container's requested `Config.Image` equals that reference. The container's reported `Image` must equal either the authenticated config digest or authenticated store target, accounting for API representation differences without accepting unrelated images. Post-run analysis revalidates the retained identity receipt and inspect snapshot, their hashes in the run plan, and the container references. It does not rehash 17 GB for every report; the fresh host preflight provides that measurement.

`local_checks/identity-correction-dMA4RU/image-identity.json` records a successful full-archive verification against the actual saved host inspection. This is read-only artifact/metadata validation, not a new host Docker execution or inference pass. The SDK compliance finding and all SDK audit gates remain unchanged.
